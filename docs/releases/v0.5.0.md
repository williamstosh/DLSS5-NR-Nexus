# NR Nexus v0.5.0 — 编辑复用实验与按需备档 / Edit reuse experiments and on-demand preparation

<!-- Previous: v0.4.3 -->

[简体中文](#简体中文) · [English](#english)

## 简体中文

### 版本亮点

本版本汇总 v0.4.3 之后的隔帧编辑复用阶段成果，并新增自适应「按需备档（实验）」。全档预备仍为默认；x2 编辑复用须手动开启并满足限定条件。最新 FG On 准入与专用输出诊断仍属于开发实验。

### 新增功能与改进

- 新增默认关闭的 x2 编辑复用配置实验：每两帧生成一次 NR 编辑，中间帧按运动重投影编辑，拒绝区域保留当前原色。普通包支持限定的原生 DX12 Upscaled（FG 关闭）及 XeFG Present 单 Backbuffer 路径，包含 FP16 scRGB 与适用的 HDR10/PQ；操作和具体限制见玩家指南。
- 自适应「预备方式」可选全档预备或按需备档（实验），保留所选档数和最低比例。按需备档减少同时保留的档位，新的冷档仍需准备；全档预备继续优先保证就绪后的切换。
- 增加离线回归、受保护采集及有界 FG 输出诊断工具。专用控制、输出探针和像素标记不进入普通 Publishing 安装包；私有 PSO、Bridge 自适应及隔帧与自适应组合实验保持各自默认关闭的边界。

### 修复内容

- 改进自适应准备中断、资源失败后的安全回收和重新准备，累计比较连续细档收益，收益不足时恢复较高画质。
- 修正隔帧运动／深度与 jitter 对齐，补齐 HDR10 颜色契约及工作尺寸与输出尺寸的区分。
- 改进 XeFG 来源、设备接口及关闭回执的身份识别，隔离原生 pre-FG 运行时上下文，并修正低尺寸 SDR 传输与不支持条件下的回退。

### 验证情况

发布前执行完整本地软件预检，并由远端核心回归独立复核；main 仅复用完整源码树相同的成功记录，Tag 对准确源码重新构建 Publishing，核对版本、诊断隔离、包内容及 SHA-256。

开发候选在《巫师 3》真实 XeFG On、DLSS FG On 下已记录 NR 刷新／复用、GPU 完成、Off／On 与 SDK 输出；这些观察不作为生成帧实际消费编辑像素的结论。最新专用输出诊断通过专用 Release 构建、355 项 CPU／MOCK 及单项 WARP 验证，未部署游戏。

另完成原生 DLSS FG 开启时的自适应单 Pass、全档预备、100%／75% 两档静态实测：自动降低工作尺寸、GPU 完成及资源复用有效，随后回到上档；SDK 输出约 116 FPS，未获得输出 FPS 提升。此结果不推广到 15 档、按需模式或动态画质。

### 已知限制

最新真实 SR Upscaled 下的 FG On 隔帧准入仍是默认关闭的 DEV 实验，普通安装包不开放该路径。生成帧像素消费、动态画质及微卡顿尚未验收；x2 的含义是 NR 每两帧更新一次编辑，与 FG 输出倍率分开。按需冷档创建、模型或游戏资源变化仍可能造成停顿，尚无无卡顿或显存节省比例承诺。阶段发布不扩大既有 API、跨阶段、FG 异尺寸或跨游戏兼容范围。

### 安装说明

下载 Windows x64 ZIP 与对应 `.zip.sha256` 并校验。关闭游戏，备份插件与设置，替换 `renodx-dlss5.addon64`，避免重复加载并保留许可文件。另行提供支持完整 Add-on／API 18 的 ReShade 和合法取得的兼容 `nvngx_dlssnr.dll`。安装包附中英文离线玩家手册，不包含厂商 Runtime、模型、SDK 或 ReShade 加载器。

## English

### Highlights

This release brings together the edit-reuse milestone since v0.4.3 and adds experimental On-demand adaptive preparation. Prepare all levels remains the default. x2 edit reuse requires manual opt-in and a restricted supported path. The newer FG On admission and dedicated output diagnostics remain development experiments.

### Features & Improvements

- Added an off-by-default x2 edit-reuse configuration experiment. NR generates an edit every other frame; intervening frames reproject the edit using motion, retaining current original color in rejected regions. The ordinary package supports restricted native DX12 Upscaled with FG off and XeFG single-Backbuffer Present paths, including FP16 scRGB and applicable HDR10/PQ. See the player guide for setup and conditions.
- Preparation mode offers Prepare all levels or experimental On-demand preparation while retaining the selected level count and minimum scale. On-demand keeps fewer levels resident at once, but cold levels still require preparation. Preparing all levels continues to prioritize switching between ready levels.
- Added offline regressions, protected capture tools and bounded FG-output diagnostics. Dedicated control, output probes and pixel markers are excluded from ordinary Publishing packages. Private PSO, Bridge adaptive sizing and combined edit-reuse/adaptive experiments retain their separate off-by-default boundaries.

### Fixes

- Improved interrupted adaptive preparation, safe resource retirement after failures and subsequent preparation. Successive fine steps are compared cumulatively, restoring higher quality when the benefit is insufficient.
- Corrected motion/depth and jitter alignment for edit reuse, added the HDR10 color contract and separated working and output grids.
- Improved XeFG source, device-interface and Disable-receipt identity handling, isolated native pre-FG runtime contexts, and corrected lower-resolution SDR transport and unsupported-path fallback.

### Validation

Release checks include full local software preflight and independent core regression on CI. main reuses successful evidence only for an identical complete source tree. The tag rebuilds Publishing from the exact source and verifies version, diagnostic isolation, package contents and SHA-256.

Development candidates in The Witcher 3 with real XeFG On and DLSS FG On recorded NR refresh/reuse, GPU completion, Off/On and SDK output. These observations do not establish that generated frames consumed the edited pixels. The latest dedicated output diagnostics passed a dedicated Release build, 355 CPU/MOCK checks and one WARP case; they were not deployed in game.

A separate static check used native DLSS FG, one pass, full preparation and two levels at 100%/75%. Automatic downscaling, GPU completion and resource reuse worked, followed by a return to the upper level. Estimated SDK output remained about 116 FPS, with no output-FPS improvement. This result does not extend to fifteen levels, On-demand mode or dynamic image quality.

### Known Limitations

The newer real-SR Upscaled FG On edit-reuse admission remains an off-by-default DEV experiment, unavailable in the ordinary package. Generated-frame pixel consumption, dynamic image quality and microstutter await acceptance. x2 refers to updating the NR edit every two frames, separately from the FG output multiplier. Cold On-demand creation and model or game-resource changes may still stall; no stall-free operation or percentage VRAM saving is claimed. This milestone does not expand existing API, cross-stage, mismatched-FG-size or cross-game compatibility.

### Installation

Download and verify the Windows x64 ZIP and matching `.zip.sha256`. Close the game, back up the add-on/settings, replace `renodx-dlss5.addon64`, avoid duplicate active copies and retain the licenses. Supply ReShade with full add-on/API 18 support and a legally obtained compatible `nvngx_dlssnr.dll` separately. The package includes the bilingual offline player guide; vendor runtimes, models, SDKs and the ReShade loader are not bundled.
