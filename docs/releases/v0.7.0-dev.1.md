## 简体中文

### 版本亮点

这是尚未发布的开发版本。实验功能使用普通设置入口，普通构建和带诊断控制的构建遵循相同执行条件。实验标签说明适用输入、失败退路和待验收范围。

### 新增功能与改进

- 原生 DX11 Bridge 的合格超分后输出可使用已有自适应分辨率开关。已经开启自动的配置会在输出归属、档位和交付就绪后开始调节；关闭自动恢复手动上限。
- 原生 DLSS FG 的合格 Pre-FG Present 输入使用已有 x2 开关，支持刷新、复用和同帧后续 MFG 的完整结果重交；输入不满足时保留普通 Pre-FG 或原 SDK 输入。
- 自适应与 x2 同开时，兼容上限继续复用，真实换档先刷新。符合条件的 DX12 两档单层 B 可在低档复用；缺低档组合凭据时仍可自动试档，低档改为逐帧处理。
- 自适应区新增资源策略：默认沿用原预备方式，以及保留兼容模型、上限容量复用、上限容量按需准备三个实验选项。保留原有档数、最低比例和普通按需选择；不适用时显示实际退路。
- 方案槽将新策略独立保存，退回 v0.6.0 时保留原有方案内容；旧 INI 缺少新键默认沿用原预备方式。普通 Present 继续默认每帧，旧预设的缺键及显式 0／1 保持原义。

### 修复内容

自适应分辨率按当前输出的可靠 FPS 调节。持续欠帧时，每次下降一个相邻可用档，直到达到目标或最低档。最低档仍欠帧时报告未达目标。恰好达到目标时保持当前档，只有帧率持续高于目标且余量充足时才试升一档。每次换档都从完整交付后开始暖机，再用新采样判断。试升后能稳定守住目标就保留高档，持续欠帧则回到原低档，并记住这次失败和试升前的稳定帧率。同等条件下，只有低档稳定帧率较上次试升前明显提高且仍有足够余量，才重试这一步。

普通输出 FPS 独立于低档 x2 所需的 FG 关闭凭据。NR GPU 耗时用于诊断，完整 x2 周期仍按每基础帧计时。两种构建均停止用独立 Reflex marker 补游戏帧分母，可靠的常规标签和 SDK 实测计数继续按其来源使用。

修复开启遮罩时预备 HDR 自适应档位的资源绑定错误。

修复 XeFG 保持开启时，从 Present 切换到 Render 或 Upscaled 后 NR 持续等待 DLSS 的问题。已完成的增强不会因嵌套调用被误判为尚未交付，可信的输出来源登记也不再遗漏。

### 验证情况

普通与诊断构建的五项入口、拒绝与恢复路径已完成同输入离线对照（WARP＋模型替身）。Release、Debug、发布包隔离及多语言界面检查通过；四档资源回退另完成真实 GPU／NR Runtime 对照。

### 已知限制

低档 x2 和备用资源策略有各自的 Runtime、模型、格式、角色与档位条件。上限容量的已有合成图像对照保留少量 FP16 数值差异，尚未确定其视觉影响。冷档准备可能短暂卡顿。[玩家指南](../USER_GUIDE.md#zh-adaptive-resolution)

《巫师 3》原生 FG Present 的早侧颜色交接和晚侧整组内容版本仍有阻塞，沿原退路处理。动态画质、主观流畅度和实际显示收益仍需人工验收。缺少可靠游戏帧标签时，固定倍率估算或动态调档可能暂停，同输出可靠的 SDK 实测帧率仍可显示。

### 安装说明

此说明对应开发源码，当前没有本版本公开安装包。加载器文件名仍为 `renodx-dlss5.addon64`；ReShade 和 NVIDIA NR Runtime 仍须独立准备。已有设置可保留，资源策略默认沿用原预备方式。使用已发布安装包的玩家继续参考 [v0.6.0](v0.6.0.md)。

## English

### Highlights

This development version has not been released. Experimental features use ordinary settings, with the same execution conditions in ordinary and diagnostic builds. Experimental labels describe supported inputs, failure fallbacks and acceptance still pending.

### Features & Improvements

- Eligible native DX11 Bridge post-SR outputs use the existing Adaptive resolution switch. Configurations with automatic sizing enabled begin adjusting when output ownership, levels and delivery are ready; turning it off restores the manual upper limit.
- Eligible native DLSS FG Pre-FG Present inputs use the existing x2 switch for refresh, reuse and complete same-frame MFG result delivery. Other inputs retain ordinary Pre-FG processing or the original SDK inputs.
- Adaptive sizing and x2 together keep compatible upper worksets reusing and refresh after real level changes. Eligible two-level, single-model-B DX12 paths can reuse at the lower level. Without lower-tier reuse evidence, automatic trials continue with per-frame lower-tier processing.
- Adaptive settings add Resource strategy: follow the saved preparation mode by default, or select experimental compatible-model retention, upper-capacity reuse or upper-capacity on-demand preparation. The selected count, minimum scale and ordinary On-demand setting are preserved; unsupported groups show their effective fallback.
- Profile slots save the new strategy separately, preserving existing profile contents when reverting to v0.6.0. Old INI files default to the saved preparation mode. Ordinary Present keeps Every present as its default, including existing missing-key and explicit 0/1 preset semantics.

### Fixes

Adaptive resolution follows reliable FPS for the current output. When FPS stays below target, NR steps down one available level at a time until it reaches the target or the minimum level. It reports when FPS stays below target at the minimum. At exactly the target, NR holds its current level. It tries one level higher only with sustained FPS headroom. Warmup starts after complete delivery at the new level. Fresh FPS samples then guide the next decision. A higher level stays in use if it consistently meets the target. If it stays below target, NR returns to the lower level and remembers the failed step and the stable FPS measured before the attempt. Under the same conditions, it retries that step only when stable FPS at the lower level has clearly improved and there is still enough headroom.

Ordinary output FPS is independent of the FG-off evidence required for lower-tier x2. NR GPU timing is diagnostic, with complete x2 cycles still measured per base frame. Both builds stop using standalone Reflex markers as game-frame denominators. Reliable ordinary tags and measured SDK counts retain their own provenance rules.

Fixed resource bindings while preparing HDR adaptive levels with masking enabled.

Fixed NR remaining in a waiting-for-DLSS state after switching from Present to Render or Upscaled while XeFG stays enabled. Completed enhancement is no longer rejected by nested NGX calls, and proven output sources are registered correctly.

### Validation

The five entry points, refusal paths and recovery behavior passed matching-input offline comparisons in ordinary and diagnostic builds using WARP and model substitutes. Release, Debug, package isolation and multilingual UI checks passed. Four-level resource fallback also passed a real GPU and NR Runtime comparison.

### Known Limitations

Lower-tier x2 and alternate resource strategies have their own Runtime, model, format, role and level requirements. Existing synthetic upper-capacity comparisons retain small FP16 differences with unconfirmed visual impact. Preparing a cold level may briefly stall. [User Guide](../USER_GUIDE.md#en-adaptive-resolution)

The Witcher 3 still has blocked early color handoff and late complete-content-version paths for native FG Present, which retain their original fallback. Dynamic quality, subjective smoothness and actual display benefits await manual acceptance. Without reliable game-frame tags, fixed-multiplier estimates or dynamic trials may pause; reliable SDK output FPS for the same picture remains visible.

### Installation

These notes describe development source; no public package for this version is available. The loader filename remains `renodx-dlss5.addon64`. ReShade and the NVIDIA NR Runtime are supplied separately. Existing settings can be kept, with Resource strategy following the saved preparation mode by default. Users of the released package should continue to follow [v0.6.0](v0.6.0.md).
