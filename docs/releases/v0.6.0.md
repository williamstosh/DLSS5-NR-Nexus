## 简体中文

### 版本亮点

x2 编辑复用扩展到符合条件的 Render／Upscaled 同阶段多层组合。继续使用画质页原有开关，默认关闭；每两个基础帧刷新一组 NR 编辑，在中间帧复用以减少模型调用。x2 与帧生成的输出倍率分别设置。

### 新增功能与改进

- 支持同一 Render 或 Upscaled 介入点的单层及多层 x2，按实际请求判断 A、B 或解析为受支持模型的 Auto。Render 仍在每个基础帧运行游戏 SR，跨介入点链继续按原流程处理。
- 多层时域 Look 沿各层当帧输入推进历史，复用帧跳过整组模型求值。使用时域滤波时，各层须为当前介入点完整分辨率；较低工作分辨率的组合按原设置逐帧回退。仅空间 Look 的异尺寸组可在满足条件时复用。
- 新增受限的普通 D3D12 scRGB Present x2：单层、全幅尺寸、FG 关闭及“游戏帧”策略，须验证同帧 SR 图像完整交付至当前 Backbuffer；来源不成立或普通 HDR10/PQ 时保留原画。XeFG Present 继续沿其既有单 Backbuffer 条件。
- 监视器显示实际请求、生效、逐帧处理或保留原画的原因；菜单帮助、14 种翻译与双语指南同步当前资格条件。

### 修复内容

- 统一已获准路径的资格和历史身份，避免仅因 FG 诊断信息或无接管的 options 变化而重复清空固定尺寸 NR 历史。
- 修正实际模型、Present 工作集、队列观察换代及 Reset 时的复用判定，并改善重投影颜色置信度和 Render 复用帧的 GPU 计时。
- 普通 D3D11 Bridge 在 GPU 完成后才交付结果，允许原 SR 与 Bridge 录制重叠；Vulkan 求值失败后恢复安全状态并重新准备。

### 验证情况

发布沿用完整本地软件预检、普通 Publishing 诊断隔离及精简远端核心复核；main 只复用完整源码树相同的成功证据，Tag 对准确源码重新构建并核版本、包内容和 SHA-256。软件与离线证据按 CPU、MOCK、WARP、原生 GPU／NGX 分别记录，不作为通用实机通过。

《巫师 3》开发候选在 4K Upscaled、FG Off、A→B 双层、同存档静态短窗中，逐帧 NR 与 x2 的基础 FPS 为 **30.54 → 37.23（+21.90%）**。共 **261 次写回、零回退**，包含 130 次双层刷新和 131 次零 Evaluate 复用，均匹配 GPU 完成。这是该场景基础帧处理口径，不是显示 FPS 或通用性能承诺，也不是最终 Tag DLL 的新增实机验收。

另一次普通 Publishing 候选实测使用《巫师 3》DX12、固定 4K Upscaled、单层模型 B，原生 DLSS FG 已开启，SDK 观测约 4×。玩家现有画质页 x2 开关累计 **600 次刷新、600 次复用、零回退**；另有 **16 个完成写回的 GPU 抽样**。这确认了普通构建中该组合的刷新与复用，不依赖 DEV 开关。本次采集未完成全部步骤，结论限于留存日志与 GPU 抽样；未测端到端增帧或逐张生成帧像素，也不套用上述 FG Off 双层的 +21.90% 数据。

普通宏 WARP＋MOCK 定向回归覆盖无接管的 FG 声明 Off→On→Off，以及单层、同分辨率双层的复用节奏和历史保持。FG On 双层实机尚未完成。

同阶段时域 Look、异尺寸时域逐帧回退、仅空间异尺寸组和多层 Render 已有离线定向证据；中英 ImGui Quick 原图及 320 项定向检查已完成。静态局部与短转镜抽查已有记录，地砖一处局部暗点的成因尚未归因。

### 已知限制

异尺寸、多层 Render、FG On 多层及动态观感尚未实机验收。拖影、闪烁、光照变化、HDR 观感和感知卡顿仍需按实际游戏比较。普通 Present 的 PQ 路线、Native DLSS FG Present 的同帧来源／交接前提仍受限，独立 FG 验证保持暂停；本版不恢复这些暂停项，也不将开发候选能力追溯为 v0.5.1 安装包已有功能。

### 安装说明

下载 Windows x64 ZIP 与对应 `.zip.sha256` 并校验。关闭游戏，备份插件和设置，替换 `renodx-dlss5.addon64`，避免重复加载并保留许可文件。包内继续保留 README、玩家指南及可本地打开的双语 HTML 手册。另行提供支持完整 Add-on／API 18 的 ReShade 和合法取得的兼容 `nvngx_dlssnr.dll`；不附带厂商 Runtime、模型、SDK、ReShade 加载器或内部研究稿。

## English

### Highlights

x2 edit reuse now supports eligible same-hook multi-pass Render/Upscaled configurations. It uses the existing Quality-page toggle and remains off by default. NR refreshes a group of edits every two base frames and reuses it between refreshes to reduce model calls. x2 is separate from the frame-generation output multiplier.

### Features & Improvements

- Supports eligible single-pass and same-hook multi-pass Render/Upscaled x2, using the actual A, B or supported Auto model request. With Render, the game's SR still runs on every base frame. Mixed-hook chains retain their existing processing.
- Per-pass temporal Look advances history from each pass's current-frame input while reuse frames skip model evaluation for the group. Temporal filtering requires full hook-point resolution in every pass; lower-resolution temporal groups run every frame with their original settings. Eligible spatial-only groups with different resolutions can reuse.
- Adds restricted ordinary D3D12 scRGB Present x2: one pass, full-frame working size, FG off and the Game frames policy, with verified same-frame SR delivery into the current backbuffer. Missing provenance or ordinary HDR10/PQ retains the game image. XeFG Present keeps its existing single-backbuffer conditions.
- The monitor explains the actual request, effective reuse, per-frame processing or original-image fallback. Menu help, fourteen translations and the bilingual guide reflect current eligibility.

### Fixes

- Shared eligibility and history identity across admitted paths, avoiding unnecessary fixed-size NR history resets from FG diagnostics or options changes without takeover.
- Corrected reuse decisions for actual model requests, Present worksets, queue-observation changes and Reset; improved warped-color confidence and GPU timing for Render reuse frames.
- Ordinary D3D11 Bridge delivers results only after GPU completion while allowing SR and Bridge recording to overlap. Vulkan recovers safe state and preparation after evaluation failure.

### Validation

Release validation retains full local software preflight, ordinary Publishing diagnostic isolation and independent core CI. main reuses successful evidence only for an identical complete source tree; the tag rebuilds the exact source and checks version, package contents and SHA-256. CPU, MOCK, WARP and native GPU/NGX evidence retain their individual scopes rather than becoming a general in-game acceptance claim.

In a fixed-save static window in The Witcher 3, a development candidate using 4K Upscaled, FG off and two A→B passes recorded **30.54 → 37.23 base FPS (+21.90%)** for per-frame NR versus x2. All **261 writebacks completed with zero fallback**: 130 two-pass refreshes and 131 reuse frames with no Evaluate, each matched to GPU completion. These are base-frame processing measurements for that scene, not display FPS, a general performance promise or a new in-game test of the final tag DLL.

A separate ordinary Publishing candidate was tested in The Witcher 3 DX12 with fixed 4K Upscaled, a single model B pass and native DLSS FG enabled, with an SDK-observed multiplier of about 4×. The existing Quality-page x2 toggle recorded **600 refreshes, 600 reuses and zero fallback**, with **16 GPU samples confirming completed writeback**. This confirms refresh and reuse for that combination in a standard build without a DEV toggle. The capture did not complete every step; these observations come from preserved logs and GPU samples. End-to-end frame-rate gain and individual generated-frame pixels were not measured; the FG-off dual-pass +21.90% result above does not apply to this test.

Focused WARP+MOCK regression under ordinary build macros covers owner-free FG declaration changes Off→On→Off, preserving reuse cadence and history for one pass and two passes at the same resolution. In-game testing of two passes with FG on remains incomplete.

Focused offline checks cover same-hook temporal Look, per-frame fallback for lower-resolution temporal groups, spatial-only mixed-resolution groups and multi-pass Render. Chinese/English ImGui Quick originals and 320 focused checks were reviewed. Static crops and short camera-turn samples were inspected; one localized floor-seam dark point remains unattributed.

### Known Limitations

Different working resolutions, multi-pass Render, multi-pass with FG on and dynamic appearance still need in-game acceptance. Ghosting, flicker, lighting changes, HDR appearance and perceived stutter need comparison in the intended game. Ordinary Present PQ, native DLSS FG Present frame provenance/handoff and the paused independent FG validation retain their existing limits. This release does not resume paused work or describe development-candidate capabilities as features already shipped in v0.5.1.

### Installation

Download and verify the Windows x64 ZIP and matching `.zip.sha256`. Close the game, back up the add-on/settings, replace `renodx-dlss5.addon64`, avoid duplicate active copies and retain licenses. README, the player guide and the local bilingual HTML manual remain included. Supply ReShade with full add-on/API 18 support and a legally obtained compatible `nvngx_dlssnr.dll` separately. Vendor runtimes, models, SDKs, the ReShade loader and internal research documents are not bundled.
